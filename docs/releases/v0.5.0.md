# JotFlow 0.5.0

A feature release. Drafting follows a thread more closely, people can add themselves to an issue, a channel can get a weekly summary of its ideas, and issues can go on GitHub Projects boards. It adds Slack files, priority labels, and an experimental `copilot` preset.

## What's new

- **Follow-ups revise the waiting card (#304).** New replies about a pending idea revise its card, which says who changed it and what. A Request Changes note does the same, and revises only the card it was made on (#330, #375).
- **One message, several actions (#335).** A pasted email with separate actions gets a card for each, up to three, each quoting only its part.
- **A quick second post adds to your first (#334).** "And the east screen." a few seconds after your idea is read as adding to it.
- **Add me, and why each assignee was chosen (#305).** An Add me button on the card, and on a filed issue's thread, lets people add themselves. Every proposed assignee shows its reason. "Assign to Sam" works without an @-mention when only one person matches (#331). `jotflow identity link` loads a team's GitHub links at once.
- **Names in a post (#331).** "For the api: …" or "put it on the support board" picks that repo or board without a question.
- **A weekly summary (#308).** An opt-in post lists a channel's ideas each week. `re: 2` in its thread adds to idea 2, and nothing in its thread is drafted (#318).
- **Projects boards (#309).** A channel lists boards, or finds them live with `board_scopes`. The agent proposes boards with a reason, and people can change them on the card.
- **Slack files (#333).** Files reach drafting by name, and with `attachments = "text"` a small text file can go into the issue, shown in full on the card.
- **Priority labels (#332), a triage guide (#317), and an `[issues]` label and title prefix (#306).**
- **Credits (#307, #396).** The issue footer credits everyone who contributed. The card shows those names before approval, and the footer names no one else.
- **Questions can check an issue's status (#273)**, and a bot mention in an issue's thread can now become a follow-up card, not only a question (#329).
- **An experimental `copilot` preset (#59, #288)**, for GitHub Copilot CLI with OpenAI, Azure or Anthropic models. The codex preset checks each model's tools at startup (#220) and works with `read_paths` (#274).
- **`jotflow rebuild --from-github` (#256)** restores the database from JotFlow's own issues.

## Security

- **emSign roots distrusted (#360).** Both images distrust eMudhra's four emSign roots, after an intermediate under them was compromised. Every agent run's Node uses the image's cleaned store. A service with an emSign certificate stops working until that certificate is replaced.
- **Code-loading Node options are refused (#294).** The agent runners refuse to start when `NODE_OPTIONS` holds an option outside a short allowlist. Check `agent.env` and `agent-exec.env` before upgrading.
- **No model catalog fetch (#284).** The codex preset no longer fetches OpenAI's model catalog.

## Upgrade

Read [Upgrading to 0.5.0](https://github.com/Jnkman787/jotflow/blob/main/docs/deployment.md#upgrading-to-050) first. It covers the `NODE_OPTIONS` check, the optional token permissions, board creator ids to pin, and the changes people will notice. Take a backup, then bump both images to `0.5.0`, `jotflow` and `jotflow-agent`, since both changed:

```sh
uvx jotflow@0.5.0 init
docker compose up -d
```

Or set `JOTFLOW_IMAGE_REF` and `JOTFLOW_AGENT_IMAGE_REF` in `.env` to the `0.5.0` images. If `.env` sets them, setup alone leaves you on the old images. The default Compose files and the Slack manifest are unchanged. Only a channel that sets `attachments = "text"` needs the `files:read` scope and a reinstall.

**Rolling back:** this release adds database migrations 16 to 24, so roll back by restoring the backup from before the upgrade. Also remove every key a 0.4 JotFlow doesn't know from `jotflow.toml`: `[issues]`, `github_org`, `attachments`, `triage_guide`, `priority_labels`, `summary`, `aliases`, `owner_hints`, `boards` and `board_scopes`.

# JotFlow 0.4.0

A feature release. Teams can now ask JotFlow questions in Slack, point a channel at repos by name pattern, set house rules for issues, and verify GitHub links. Several stronger safety options are available too.

## What's new

- **Ask questions (#57).** Start a message with `ask:` or @-mention the bot in a watched channel. The agent answers in the thread from the channel's topics and `/jotflow help`, with no GitHub access, no links and no pings. Only workspace members can ask, with hourly and per-person limits. Turn it off with `[questions] enabled = false`.
- **Repos by pattern (#236).** A channel can feed every repo an owner has, or those matching a pattern, with a `[[channels.<id>.scopes]]` table. New and renamed repos appear within 15 minutes, with no restart. `/jotflow repos <word>` searches the list.
- **House rules for issues (#216).** Per repo, team-written `conventions` for the drafting agent, and an enforced `title_pattern`.
- **Related issues on the card (#36).** Cards list up to three issues the agent found close to the idea. **Same as** links the thread to one instead of filing a duplicate, and **Not a duplicate** undoes it.
- **Verify a GitHub link (#195).** `/jotflow verify` proves a login is yours, and drops "(unverified)" from cards.
- **`jotflow rebuild` (#38).** It restores JotFlow's database from Slack if it's lost without a backup.
- **Readable help (#257).** `/jotflow help` and `/jotflow repos` have headed sections and bulleted repos.

## Opt-in safety and reach

- **Per-run uids (#181).** With `JOTFLOW_RUNNER_ISOLATION=uid` and the new `docker-compose.isolation.yml`, runs of one kind can't read each other's secrets. It needs API-key logins.
- **Reading repo docs (#209).** With `read_paths`, the drafting agent can read listed text files, such as design docs. The read token then needs Contents: Read, which covers every file in the repos it reaches. Codex can't be used with `read_paths`.
- **No stray @-mentions (#250).** Drafted issues can't ping anyone outside the conversation, and this is always on.

## Upgrade

Take a backup first, as the [deployment guide](https://github.com/Jnkman787/jotflow/blob/v0.4.0/docs/deployment.md#upgrading-and-rolling-back) shows. Then bump both images to `0.4.0`, `jotflow` and `jotflow-agent`, since the agent image changed too:

```sh
uvx jotflow@0.4.0 init
docker compose up -d
```

Or set `JOTFLOW_IMAGE_REF` and `JOTFLOW_AGENT_IMAGE_REF` in `.env` to the `0.4.0` images. If `.env` sets them, setup alone leaves you on the old images. The default Compose files are unchanged, and no Slack app change is needed.

**Rolling back:** this release adds database migrations 14 and 15, so roll back by restoring the backup from before the upgrade. Also remove any new settings from `jotflow.toml` (`scopes`, `read_paths`, `conventions`, `title_pattern`, `[questions]`), because older versions refuse them.

# JotFlow 0.1.1

A fix release for 0.1.0. It closes the known issue in 0.1.0's release notes: a runner secret could reach a public address through DNS (#234). It also fixes two setup gaps found during a clean-machine install.

## Upgrade

Take a backup first, as the [deployment guide](https://github.com/Jnkman787/jotflow/blob/v0.1.1/docs/deployment.md#upgrading-and-rolling-back) shows. Then, from your JotFlow folder:

```sh
uvx jotflow@0.1.1 init
docker compose up -d
```

Answer `y` when setup asks to replace each Compose file. The DNS fix is in those files, so changing only `JOTFLOW_IMAGE_REF` and `JOTFLOW_AGENT_IMAGE_REF` in `.env` isn't enough this time. Setup keeps your tokens, `jotflow.toml` and secrets, and saves each old Compose file as a `.bak`. If your `.env` sets `JOTFLOW_IMAGE_REF` or `JOTFLOW_AGENT_IMAGE_REF`, change both to `0.1.1` or remove them: they override the Compose files' pins, so you would keep running the 0.1.0 images. No Slack app change is needed.

## Security

- **Runner secrets and run tokens go only to private addresses (#234).** JotFlow resolves each runner's name once and sends the secret only if every address is private, loopback or link-local, including 100.64/10 for VPNs such as Tailscale. It then connects to the address it checked. Each runner checks JotFlow's MCP host the same way before every run. The Compose files turn off DNS search domains, so a service that isn't running no longer resolves through your network's resolver to a public host. `JOTFLOW_RUNNER_ALLOW_PUBLIC` and `JOTFLOW_MCP_ALLOW_PUBLIC` opt in to public addresses, for the rare setup that needs them.
- A missing runner now fails its startup check in about 15 seconds, not 2 minutes.

## Fixes

- **A model key the runner never passes is caught (#239).** If an agent env file set `ANTHROPIC_API_KEY` without listing it in `JOTFLOW_AGENT_ENV_ALLOW`, every run failed to sign in, and `jotflow check` still passed. Setup now adds the key and says so. `check` fails and names the line to set.
- **The "Agent model" prompt shows its default,** like setup's other prompts (#239).
- **`/jotflow help` and `/jotflow repos` work with many repos or long repo names (#231).** Their replies now fit Slack's block limits, and they're plain text, so they can't ping or link.

# JotFlow 0.2.0

This release changes who may approve in a channel with an approver list. A listed approver may now approve a proposal drawn from their own messages. It's a minor release, not a patch, because it changes behaviour on upgrade.

## What changes

- **A listed approver may approve their own proposal (#244).** With `[approval] approvers` set, a listed approver can approve by the button, the approval reaction or Retry, even when the proposal came from their own messages. Until now that was always refused, with "someone else needs to approve it".
- **Keeping the old rule.** Set `[approval] require_second_approver = true`. It needs an approver list: JotFlow refuses the setting without one, and `jotflow check` names the fix, so a team can't believe it requires two people when it doesn't.
- **Unchanged:** only listed approvers may approve, and guests and external users never can. With approvers off, anyone in the channel may approve, as before. `/jotflow help` now says which rule applies in the channel.

The [threat model](https://github.com/Jnkman787/jotflow/blob/v0.2.0/docs/threat-model.md#accepted-in-v1) records the trade-off: under the new default, one listed approver acting alone can approve their own idea, including a draft they edited from the card.

## Upgrade

Take a backup first, as the [deployment guide](https://github.com/Jnkman787/jotflow/blob/v0.2.0/docs/deployment.md#upgrading-and-rolling-back) shows. The Compose files and the Slack app are unchanged since 0.1.1, so either way works:

```sh
uvx jotflow@0.2.0 init
docker compose up -d
```

Or set `JOTFLOW_IMAGE_REF` and `JOTFLOW_AGENT_IMAGE_REF` in `.env` to the `0.2.0` images, then run `docker compose up -d`.

If you're upgrading from 0.1.0, follow the [0.1.1 upgrade notes](https://github.com/Jnkman787/jotflow/blob/v0.2.0/docs/releases/v0.1.1.md#upgrade) as well. Its DNS fix needs the 0.1.1 Compose files.

To roll back to 0.1.1, remove `require_second_approver` from `jotflow.toml` first, because 0.1.1 refuses keys it doesn't know.

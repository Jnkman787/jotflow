# JotFlow 0.1.0

The first release of JotFlow. It turns the ideas your team posts in Slack into GitHub issues. Your team's own agent drafts each one from the whole thread, and a person approves the card before anything is written.

## Try it

From an empty folder on a machine with Docker:

```sh
uvx jotflow init
docker compose up -d
```

Setup walks you through creating the Slack app, choosing channels and repos, and giving the agent containers their GitHub tokens. The [README](https://github.com/Jnkman787/jotflow#readme) explains each step, and the [deployment guide](https://github.com/Jnkman787/jotflow/blob/v0.1.0/docs/deployment.md) covers running it on a server.

## Highlights

- **Post as usual.** JotFlow waits for a thread to go quiet, then drafts from all of it. `idea:`, `bug:`, `re: web#42`, and `skip:`, or a reaction, steer it when you want to.
- **One card per proposal.** It shows the exact issue that will be written, with the repo, labels, and assignees, and it can be edited before approval.
- **You approve, the agent writes.** An approval locks exactly what the card showed. The write runs in a separate container that holds the only token able to write.
- **Your agent, not ours.** The Claude Code preset is locked down to JotFlow's tools and GitHub's own MCP server. The `command` preset runs your own agent.
- **Help in Slack.** `/jotflow help` explains everything privately, a pinned guide covers the basics, and mistyped keywords get a quiet correction.
- **Run it simply.** It runs as one Compose project with no port published. It reports a health status, holds no GitHub credentials, and keeps no thread text.

## Before you rely on it

The [threat model](https://github.com/Jnkman787/jotflow/blob/v0.1.0/docs/threat-model.md#accepted-in-v1) lists what this release deliberately leaves open. The two most teams should know first:

- By default, anyone in a channel can approve. Turn approvers on for channels with wide or external membership.
- GitHub logins linked from Slack are self-declared, and cards mark them "(unverified)".
